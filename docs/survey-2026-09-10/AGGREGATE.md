# Survey of every foreman, supervisor and desk, 2026-09-10 — aggregate

20 answers: 9 Foreman-era (runtime v0; v1–v4b; panel; gauge; panel-perf; both merge desks; trial-frictions; v5 supervisor) and 11 boxes/ESC-era (orchestrator; engine; api; corpus; discovery; sidequests; merge desk; four Astra supervisors/reviewers). Raw answers beside this file. Counts below are voices that said it independently.

## Design amendments the survey demands (ordered by voices)

1. **A verify must be proven able to fail before the node is accepted (11).** The runtime runs the node's verify on the base (must be red) and on the head (must be green); a node whose verify was never observed red is refused. Also: the verify must resolve and run at all (panel: named a program that did not exist; trial-frictions: 20 minutes to find a runnable one); the door refuses an EMPTY verify, never judges its vocabulary (v0's honest `test "$(cat …)"` was refused by an allowlist). Nodes carry the property under test / what a wrong answer looks like, not only a command (engine, discovery). Verify may be revised with a reason (sidequests). Verify's evidence scope is typed: source test / production load / fixture / live (astra ×2).
2. **A target move invalidates recorded evidence (7).** A green, a review verdict, a measurement is bound to head+base; automatic rebase re-runs the check and marks prior verdicts stale rather than carrying them. After a landing, the design says what the supervisor's branch is (v1–v4b lost a round to this).
3. **Map facts carry provenance, time and commit; derived facts inherit the weakest label (6).** Facts that are copies of something owned elsewhere get a re-derivation leaf (corpus check table drifted for months; discovery's index recorded CONFIRMED on unchecked inputs). Machine prerequisites live in the map: tunnels, port-forwards, credential paths, filesystem quotas, fixture containers, tested execution capabilities.
4. **Shared mutable resources set concurrency, not job count (5).** Fixture databases, locks, /tmp: reserved with a count like model slots; the runtime refuses to start a fixture-backed job past it. Worktrees and worker scratch live on disk by construction — /tmp tmpfs killed every shell on the machine three separate times.
5. **Silence is not a pass (6).** A check that looked in the wrong place, a reviewer that died on quota or an access flag, a negative result with no positive control: all distinct states from "found nothing wrong", recorded as such, never collapsed into green. Preserve both attempts of a retried review.
6. **The build that serves a verb or a verify is pinned and recorded (5).** Absolute interpreter in the MCP config and per-repository policy; every write records the runtime commit that served it; a role page is generated from the verbs the running build actually has (panel's prompt promised withdrawn verbs; gauge proved v3 with main's code).
7. **Authority arrives through the runtime, never through a relayed message (4).** HALTs, "the owner said", deletions relayed by peers: the design states that only inbox answers and rulings on the ledger carry the owner's word.
8. **Landing script details (3).** Refuse an empty range before running the check; re-run the check AFTER the update, on the tree that will actually land; record commits dropped by rebase; per-repository policy may name a landing script (Orbit's build→pin→dry-run→rollout→assert loop ran outside every node), not only a PR rule.
9. **Smaller but real:** which process owns the queue tick (v5 supervisor); milestones carry their own verify; rebase item precedes landing item; phased reservations (builder first, reviewers later) instead of whole-team-for-the-duration; a pool out for days needs a foreman-level override of "backup only after failure"; a seeded first checkpoint at mint so orientation is not "silent"; refusals appealable with a reason; cross-front dependencies; a review-round budget with a defined escape / redesign state; a flake register and "green is a count, not a state"; the write door names the rejected field; node bodies unbounded; a node kind for derived artifacts (doc + tests from one source); tool-level denies, not prose, for role boundaries; the foreman refuses `--task` titles that match nothing.

## What the survey confirms as right
Deleting the desk (unanimous, incl. both desks); runtime-owned starts and waits; automatic rebase; front-scoped storage; map seen/assumed (would have caught panel-perf's wrong diagnosis and discovery's index); mechanical queues; foreman-held quotas; refs resolved against the remote (the single most-wanted clause on the ESC side).

## Team: what every supervisor that ran workers agreed on
- **Ceiling: two builders per supervisor on one codebase** (8 voices), three to four only where leaves are disjoint by construction (sidequests 4 Muse; Orbit 4 Grok; a research front 6). The bottleneck named every time: the supervisor's own verification, which is serial.
- **Count = min(independently VERIFIABLE leaves, supervisor verify throughput, shared-fixture slots).** Independence is judged at verify time, by files/modules touched and resources shared, never by task count. Repositories add landing lanes, not builders. Leaves resting on ASSUMED map facts run alone and first.
- **Model from the verify's shape:** a number / diff / golden file → cheap model, no review; a behaviour / property / security boundary → strong builder plus an EXECUTING reviewer. Pairs only for structural reasons (two independent readers).
- **Signals:** add a worker when ready independent leaves wait and the verify queue is empty; remove one when a conflict was resolved by judgement, two workers touch one file, flakes appear, or a returned job waits >10 min; change model when the failure is omission (plausible, incomplete), the same class repeats, or the worker explains a failure instead of fixing it; downsize when jobs return in <15 min.
- **A verify that goes red beats a second read.** Where review is bought, buy the reviewer that executes.

## Model behaviour (concrete, cross-front)
- **Grok 4.6 high** — best builder on every front that used it; reads specs adversarially (refused a check that could only pass). Fails: tests that look like protection and cannot fail; scope creep; history amend after the finish marker; routes around a held lock; calls flakes "environmental"; escaped a role boundary via the board. Forbid: choosing its own done-when, deciding a failure is environmental, skipping a lock, any write after the marker, untrusted-input topics; deny by tool permission and the six GROK env switches.
- **Muse xhigh** — honest self-reports, cheap, obedient to one-page specs with the exact judging command and explicit must-not lists. Fails by agreeing (confirmed 58/58 rows on wrong trees), tests that cannot fail, unstated invariants (two clocks), dies ~half of long runs on idle timeout, launders `[REDACTED]` over Bearer-shaped text into code. Forbid: sole author of the only test without a named failure mode, critical-path work, auth-touching prose, anything it cannot be made to quote. Make every unit idempotent so a death costs one unit.
- **Opus 5 (supervisors)** — verifies by running, honest ledgers. Fails: confident wrong facts, invented timestamps and line refs, `git add -A` in a worker's tree, `git checkout <file>` destroying worker edits, findings naming a component never executed, yellows for covered decisions, long silent orientation. Forbid: typing any number not pasted from a command; naming a cause without reading the command line.
- **Astra 6** — highest-value reviewer when it executes (found P1s green tests hid); fails: sandbox silently denies sockets so "runs" become reads, 40+ min, drifts into redesign, reaches for the board, verdict vocabulary drift, dies on access flags with no verdict. Forbid: bypass-sandbox flag, supervising, redesign of settled design; require network access or treat the round as a read.
- **Sol high** — strongest executing reviewer on the ESC side; over-reports, malformed polling, APPROVE instead of the gate word, access-flag terminations.
- **Fable 5.1** — judgement, tool surfaces, corrections (caught invented timestamps, a merge never announced); risk: long silent reading; not for mechanical work.
- **Sonnet** — one review (quota exit first, then fine); otherwise labels only.

## Rulings that were needed and never given (make them rules before v5's first job)
What an intruder is · a surviving mutation must be classified (gap / ineffective / vacuous test) before moving on · what to do when the verify does not exist (file error, stop) · which build proves a proof and whether records written by the wrong build are evidence · may the landing move a local ref · landing grain · is a worker's correct out-of-scope fix accepted · does a same-model pair count as a pair (no for recall, yes for mechanics) · who owns a fact that turns out wrong after work was built on it · what counts as the owner's word when relayed · who decides when review rounds are exhausted · what a check's silence means (refused by default) · may a repair of review findings land on the supervisor's verify without re-review.

## Lines worth carving above the door
Only running is evidence; three green claims about one thing are still claims. A test of a check must be mutated. Construct the condition, never wait for it. A note explaining a hazard inside the code that has it reads as handled. Check what your check can see. Agreement is evidence only when the reasons agree. Run one producer-to-consumer probe before parallelising six consumers. When you find a defect in your tooling, check the product for the same shape. Report the thing that makes you look bad, by name, immediately.
